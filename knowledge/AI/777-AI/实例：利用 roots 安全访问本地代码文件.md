# 实例：利用 roots 安全访问本地代码文件

![[实例：利用 roots 安全访问本地代码文件-0a81deb8.docx]]

## 内容

假设你正在使用一个 **AI 编程助手（MCP Client）**，它运行在一个本地代码编辑器（如 VS Code 或 Cursor）内。该助手需要连接一个 **本地文件系统 MCP Server** 来读写你的项目文件。

**场景：限制 AI 只能访问当前项目目录**

用户在 /Users/user/Projects/MyWebApp 目录下工作，并希望 AI 助手帮助他修改该目录下的文件。

  ----------------------------- ------------------------------------------------------------------------------------------------- --------------------------------------------------------
  角色                          动作                                                                                              目的

  **MCP Client (AI 编辑器)**    启动时，Client 询问用户或读取配置文件，确定当前项目的工作目录是 /Users/user/Projects/MyWebApp。   Client 需要将这个安全边界通知给本地的文件系统 Server。

  **本地文件系统 MCP Server**   Server 启动，等待 Client 连接，但它**不知道**可以访问哪个目录。                                   Server 必须等待 Client 告知它**被授权**的访问范围。
  ----------------------------- ------------------------------------------------------------------------------------------------- --------------------------------------------------------

**roots/list 的安全边界定义流程**

Client 通过 roots/list 将授权的目录告诉 Server：

  ---------------------------- ----------------------------- -------------------------------------------------------------------------------------------------------------------- ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  步骤                         角色                          动作/方法                                                                                                            描述

  **1. Client 传递授权目录**   **MCP Client**                在初始化或连接 Server 后，Client **发送** roots/list 请求给 Server（或者在 Server 启动时传入）。                     Client 告诉 Server，它可以访问一个或多个**根目录 (Roots)**。例如：\[{\"uri\": \"[[file:///Users/user/Projects/MyWebApp/]{.underline}](file:///Users/user/Projects/MyWebApp/)\", \"title\": \"Current Project\"}\]。

  **2. Server 建立访问边界**   **本地文件系统 MCP Server**   **接收**到 roots/list 列表，Server 严格地**将所有文件操作限制**在这个 URI 边界内。                                   Server 现在知道，任何对 /Users/user/Documents/SecretFolder 的请求都应该被**拒绝**。

  **3. LLM/Agent 调用 Tool**   **AI Agent (LLM)**            LLM 决定调用 Server 的 Tool：read_file(path)。 Agent 请求读取文件 /Users/user/Projects/MyWebApp/src/index.js。       Tool 调用带着**相对路径**或**根路径**下的绝对路径发起。

  **4. Server 权限校验**       **本地文件系统 MCP Server**   Server 在执行 read_file Tool 之前，会**检查**请求的路径是否包含在任何一个已授权的 **Root** 边界内。                  路径 /Users/user/Projects/MyWebApp/src/index.js 在授权范围内，**允许执行**，Server 返回文件内容 Resources。

  **5. 拒绝未授权访问**        **本地文件系统 MCP Server**   如果 Agent 尝试读取 /Users/user/.ssh/id_rsa，Server 会发现该路径不在已授权的 Root 列表中，并立即**返回权限错误**。   **Root 成功阻止了 AI Agent 访问敏感的、未授权的系统资源。**
  ---------------------------- ----------------------------- -------------------------------------------------------------------------------------------------------------------- ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

**总结：roots 的核心价值**

- **安全隔离 (Security Isolation)：** 这是 Root 的首要目标。它确保了 AI Agent 只能访问用户明确授权的本地资源，防止了潜在的恶意或意外的文件系统访问（即所谓的 **"沙箱"** 机制）。

- **上下文清晰 (Clear Context)：** Root 机制让 Server 和 LLM 都清楚地知道"什么是项目内文件"和"什么是项目外文件"，帮助 LLM 更准确地理解文件操作的意图。

在本地 Agent 应用场景中，**Root** 是保障用户数据安全和隐私的**第一道防线**。
