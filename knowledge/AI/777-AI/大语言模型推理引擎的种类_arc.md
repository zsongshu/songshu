# 大语言模型推理引擎的种类

目前主流的几类引擎及其核心特点。

|     |     |     |     |
| --- | --- | --- | --- |
| 引擎类别 | 核心目标 / 设计哲学 | 代表性引擎 | 一句话定位 |
| **高并发与服务化引擎** | 极致优化**吞吐量**与**内存利用率**，满足生产环境高并发需求 | vLLM, SGLang, Hugging Face TGI, XInference | 为大规模、高性能 API 服务而生，是企业部署的首选。 |
| **硬件专属优化引擎** | 深度绑定特定硬件，**榨干硬件性能**，追求极限速度与能效 | TensorRT-LLM (NVIDIA), LMDeploy (国产芯片) | 在特定硬件（尤其是NVIDIA GPU）上提供顶尖性能。 |
| **轻量级与本地化工具** | **降低使用门槛**，让大模型能在消费级硬件上便捷运行 | Ollama, LM Studio, llama.cpp | 让每个人都能在个人电脑上轻松运行大模型。 |
| **通用与编译器类引擎** | 追求**跨平台兼容性**与**通用优化**，一次编写多处高效运行 | MLC-LLM, Hugging Face Transformers Pipeline | 致力于成为兼容性最好的“万能钥匙”。 |

### **🔧 核心区分维度详解**

了解这些引擎的种类后，我们可以从以下几个关键维度进行更深度的比较，这往往也是你选型时的决策依据：

1. **核心技术（如何管理内存和注意力）**
	* **内存管理**：这是区分引擎性能的关键。**vLLM** 的核心创新 **PagedAttention** 借鉴了操作系统的虚拟内存分页思想，将KV Cache（键值缓存）打散成块来管理，极大地减少了内存碎片，将显存利用率从传统的约60%提升至95%以上。而 **SGLang** 的 **RadixAttention** 则专注于解决提示词前缀重复计算的问题，它通过基数树（Radix Tree）缓存和复用公共前缀的KV Cache，在处理多轮对话等场景时，吞吐量相比vLLM有数倍提升。
	* **批处理技术**：**连续批处理（Continuous Batching）** 是现代高性能引擎的标配。它改变了传统“静态批处理”需要等一个批次所有请求都处理完再继续的方式，可以动态地将新请求加入计算队列，让GPU时刻保持“忙碌”，显著提高利用率。
2. **性能特点（侧重延迟还是吞吐量）**
	* **低延迟**：指单个请求从发出到收到第一个token的时间（Time To First Token, TTFT）。这对交互式应用（如聊天）至关重要。**TensorRT-LLM** 通过预编译和内核级深度优化，在此项上通常表现最佳。
	* **高吞吐量**：指单位时间内系统处理的总token数（Tokens Per Second, TPS）。当需要批量处理大量文本（如摘要、翻译）时，吞吐量是关键。**vLLM** 和 **SGLang** 在这方面是佼佼者。
3. **硬件与生态兼容性**
	* **硬件支持**：引擎对硬件的依赖各不相同。**TensorRT-LLM** 和 **LMDeploy** 分别深度绑定NVIDIA GPU和国产AI芯片。而 **llama.cpp** 和 **MLC-LLM** 则对CPU和跨平台部署更为友好。
	* **模型格式**：不同的引擎对模型文件格式有偏好。例如，**Ollama** 主要使用 **GGUF** 格式，而 **vLLM**、**SGLang** 等则更好地支持 **Safetensors** 或 **PyTorch** 格式。

### **💡 如何选择：场景驱动的选型指南**

结合以上维度，你的具体应用场景是最终的决策依据：

* **企业级高并发API服务**：若你的目标是构建一个需要服务大量并发用户的生产环境，**vLLM** 是目前经过广泛验证的、平衡性最佳的选择。如果您的场景涉及大量**多轮对话**或需要**复杂的结构化输出**（如直接生成JSON），**SGLang** 会因其前缀复用优势带来更高的吞吐量。
* **追求NVIDIA GPU上的极致性能**：如果你的基础设施全是NVIDIA GPU，且对推理**延迟有极致要求**，**TensorRT-LLM** 能带来最接近硬件极限的性能。
* **个人开发、测试与隐私敏感应用**：如果你是个人开发者或需要在内部快速验证想法，**Ollama** 或 **LM Studio** 能让你在几分钟内就在笔记本电脑上运行起大模型，非常简单快捷。
* **边缘设备或特定国产芯片部署**：在资源受限的边缘设备上，**llama.cpp** 是经典选择。如果您的环境涉及**国产AI芯片（如昇腾）**，那么 **LMDeploy** 是经过专门优化的方案。
