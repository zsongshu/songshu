# 分布式强化学习训练框架-verl

![[分布式强化学习训练框架-verl-b8da1c61.docx]]

## 内容

**1. 为什么需要 verl？（痛点）**

传统的 LLM 训练框架（如 Megatron-LM 或 DeepSpeed）主要针对的是**预训练（Pre-training）或微调（SFT）**。但强化学习（RLHF）的流程非常复杂，通常涉及四个模型同时运行：

在 verl 的架构里，vLLM 或 SGLang 是作为 **Rollout Worker** 被集成的。

- **Actor**：生成答案。

- **Critic**：评估答案好坏。

- **Ref**：参考模型，防止学歪。

- **Reward**：打分模型。

**痛点：** 这四个家伙对资源的需求完全不同。有的吃显存，有的吃计算。如果强行把它们塞在一起对称部署，显存会炸；如果分开，模型之间频繁传输数据，速度又会极慢。

**2. verl 的"黑科技"核心：Hybrid Engine（混合引擎）**

verl 最具代表性的创新是提出了 **混合引擎（Hybrid Engine）** 的概念。

- **灵活切分（Model Sharding）**：它允许不同的模型使用不同的并行策略。比如，Actor 可能需要张量并行（TP），而 Reward 模型可能只需要数据并行（DP）。

- **显存高效（Memory Efficient）**：它能根据训练阶段，动态地在 GPU 显存和 CPU 内存（甚至 NVMe）之间搬运模型权重，极大地压榨硬件性能。

- **无缝集成**：它底层兼容了主流的算子库，比如生成阶段用 **vLLM**（推理快），训练阶段用 **FlashAttention**（计算快）。

**3. verl 的关键优势**

  ------------------ ------------------------------------------------------------------------------------------
  **特性**           **描述**

  **超高性能**       在字节跳动的内部测试中，verl 在 PPO 训练上的吞吐量通常能达到其他开源框架的 **8-20 倍**。

  **支持多种算法**   原生支持 **PPO**、**DPO**，以及最近因为 DeepSeek-R1 火出圈的 **GRPO**。

  **极易上手**       采用类似 PyTorch 的接口，且完美对接 Hugging Face 生态。

  **分布式扩展**     专门为超大规模集群（数千张卡）优化，解决了大规模 RL 训练中的通信瓶颈。
  ------------------ ------------------------------------------------------------------------------------------

**4. 谁在用 verl？**

由于 DeepSeek 最近开源了 R1 模型，并详细介绍了其强化学习的演进，很多开发者开始尝试复现。**verl 目前是社区中复现 DeepSeek-R1 强化学习流程最热门的框架之一**，因为它能很好地处理 R1 这种超长上下文和复杂的奖励逻辑。

|                                                                                                                                                                                                                                         |

|                                                                                                                                                                                                                                         |
|     - 中间的 Data Flow Control 模块负责样本预处理、Checkpoint 管理以及数据交互。这验证了前文中提到的"以数据为中心"的架构逻辑。                                                                                                          |
|                                                                                                                                                                                                                                         |
| 7.  **推理引擎的高集成度**：                                                                                                                                                                                                            |
|                                                                                                                                                                                                                                         |
|     - 架构中集成了 **Sglang**（高效推理）和 **Megatron**（分布式训练），试图结合两者的优势来提升吞吐量。                                                                                                                                |
|                                                                                                                                                                                                                                         |
| **四、 存在的优化空间**                                                                                                                                                                                                                 |
|                                                                                                                                                                                                                                         |
| - **掩盖推理空泡**：目前"等待 Rollout 数据"占据了超过 70% 的时间。如果能实现 **训练与采样的流水线并行（Pipelining）**，即在训练当前批次的同时，预先进行下一批次的采样，理论上可以显著压低总耗时。                                       |
|                                                                                                                                                                                                                                         |
| - **通信开销**：虽然模型加载/卸载时间较短（合计约 20s），但在超大规模集群下，频繁的 CPU-GPU 拷贝仍可能成为长尾延迟的来源。                                                                                                              |

| **第一步：Rollout（采样生成）------ AI 在"做题"**                                                                                                                                                                                       |
|                                                                                                                                                                                                                                         |
| - **在做什么**：模型（Actor）针对一堆问题（Prompts），生成一堆回答（Responses）。                                                                                                                                                       |
|                                                                                                                                                                                                                                         |
| - **核心原理**：这是推理过程。模型根据当前的概率分布，一个字一个字地蹦出答案。                                                                                                                                                          |
|                                                                                                                                                                                                                                         |
| - **图中的状态**：rollout_time 耗时 1722.5 秒，占比 **72.8%**，是最大的瓶颈。                                                                                                                                                           |
|                                                                                                                                                                                                                                         |
| - **💡 性能优化点**：                                                                                                                                                                                                                   |
|                                                                                                                                                                                                                                         |
|   - **引入 vLLM/Sglang**：使用图中的 Sglang 引擎，利用 **Continuous Batching**（连续批处理）和 **KV Cache 复用**来加快生成速度。                                                                                                        |
|                                                                                                                                                                                                                                         |
|   - **量化推理**：使用 FP8 或 INT8 量化，减少推理时的显存带宽压力。                                                                                                                                                                     |
|                                                                                                                                                                                                                                         |
|   - **多机并行**：增加推理卡的比重，因为这一步是纯碎的"体力活"。                                                                                                                                                                        |
|                                                                                                                                                                                                                                         |
| **第二步：Eval Server（打分评估）------ 判卷老师**                                                                                                                                                                                      |
|                                                                                                                                                                                                                                         |
| - **在做什么**：把 AI 写的代码放进沙箱（SandBox）跑一下，或者让另一个模型给这些答案打分。                                                                                                                                               |
|                                                                                                                                                                                                                                         |
| - **核心原理**：通过外部环境（Compiler, Python Runtime 等）获取客观反馈（Reward），告诉 AI 哪道题做对了，哪道题做错了。                                                                                                                 |
|                                                                                                                                                                                                                                         |
| - **💡 性能优化点**：                                                                                                                                                                                                                   |
|                                                                                                                                                                                                                                         |
|   - **高并发沙箱**：如果是代码验证，需要搭建极其强大的并发容器集群，否则打分速度跟不上生成速度，会导致训练停滞。                                                                                                                        |
|                                                                                                                                                                                                                                         |
| **第三步：Sleep & Wake up（显存搬运）------ 空间腾挪**                                                                                                                                                                                  |
|                                                                                                                                                                                                                                         |
| - **在做什么**：sleep 是把模型从 GPU 踢到 CPU；wake up 是接回来。                                                                                                                                                                       |
|                                                                                                                                                                                                                                         |
| - **核心原理**：GPU 显存很贵且有限。训练时需要存梯度，占空间大；推理时需要快速响应。为了在同一批卡上既跑训练又跑推理，只能把不用的模型临时"下放"到 CPU 内存里。                                                                         |
|                                                                                                                                                                                                                                         |
| - **💡 性能优化点**：                                                                                                                                                                                                                   |
|                                                                                                                                                                                                                                         |
|   - **参数卸载（Offloading）优化**：利用 **NVLink** 或更快的 PCIe 5.0 通道。                                                                                                                                                            |
|                                                                                                                                                                                                                                         |
|   - **预取机制**：在训练结束前，提前异步开始 wake up 操作，掩盖传输耗时。                                                                                                                                                               |
|                                                                                                                                                                                                                                         |
| **第四步：Data Preprocess（数据预处理）------ 整理错题集**                                                                                                                                                                              |
|                                                                                                                                                                                                                                         |
| - **在做什么**：把生成的对话、得分、日志（log-probs）打包成训练需要的格式。                                                                                                                                                             |
|                                                                                                                                                                                                                                         |
| - **核心原理**：将非结构化的文本转为张量（Tensor），移动到 GPU 准备计算。                                                                                                                                                               |
|                                                                                                                                                                                                                                         |
| - **💡 性能优化点**：                                                                                                                                                                                                                   |
|                                                                                                                                                                                                                                         |
|   - **零拷贝（Zero-copy）**：尽量在显存内完成格式转换，避免在 CPU 和 GPU 之间来回折腾。                                                                                                                                                 |
|                                                                                                                                                                                                                                         |
| **第五步：Actor Train（模型训练）------ 总结规律**                                                                                                                                                                                      |
|                                                                                                                                                                                                                                         |
| - **在做什么**：根据"错题集"，通过数学计算更新模型参数。                                                                                                                                                                                |
|                                                                                                                                                                                                                                         |
| - **核心原理**：使用反向传播算法（Backpropagation）。如果 AI 得到了高分，就增加生成该答案的概率；如果得分低，就降低概率。                                                                                                               |
|                                                                                                                                                                                                                                         |
| - **💡 性能优化点**：                                                                                                                                                                                                                   |
|                                                                                                                                                                                                                                         |
|   - **混合并行（TP/PP/DP）**：根据模型大小，灵活分配张量并行、流水线并行和数据并行。                                                                                                                                                    |
|                                                                                                                                                                                                                                         |
|   - **算子融合**：使用 FlashAttention-3 等高效算子，压榨 GPU 算力。                                                                                                                                                                     |
|                                                                                                                                                                                                                                         |
| **🚀 终极性能提升方案：打破"串行"咒语**                                                                                                                                                                                                 |
|                                                                                                                                                                                                                                         |
| 目前的流程是 **A -\> B -\> C -\> D** 的串行结构。提升性能最猛的一招叫 **"异步流水线（Pipelining）"**。                                                                                                                                  |
|                                                                                                                                                                                                                                         |
| 8.  **掩盖推理空泡**：                                                                                                                                                                                                                  |
|                                                                                                                                                                                                                                         |
|     - **现状**：训练的时候推理机在闲着，推理的时候训练机在等。                                                                                                                                                                          |
|                                                                                                                                                                                                                                         |
|     - **方案**：像流水线工厂一样。当第 1 组数据在进行 **Actor Train** 时，Sglang 引擎已经在同步生成第 2 组数据的 **Rollout**。                                                                                                          |
|                                                                                                                                                                                                                                         |
|     - **效果**：理论上可以将总耗时减少 **30%\~50%**，因为那 1722 秒的"等待"时间被训练时间重叠掉了。                                                                                                                                     |
|                                                                                                                                                                                                                                         |
| 9.  **异构部署**：                                                                                                                                                                                                                      |
|                                                                                                                                                                                                                                         |
|     - 不要在同一批卡上切来切去（Sleep/Wake up）。                                                                                                                                                                                       |
|                                                                                                                                                                                                                                         |
|     - 专门拿一批推理性能强的卡（如 A10/L40S）做 Rollout，拿一批计算性能强的卡（如 H800/H20）做 Train。数据通过高速网络（RDMA）传输。                                                                                                    |
|                                                                                                                                                                                                                                         |
| **小白建议**：先盯着那个 **1722.50s** 的等待时间看，只要能让推理和训练同时跑起来，你的性能就能起飞！                                                                                                                                    |
