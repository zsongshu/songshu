# 1. State of DevOps Report （Google DORA）

2014年至2025年DevOps现状报告走过了十二年历程，它的发行公司DORA，在国内不像 Gartner 有那么高的知名度，但在全球，DORA 是研发效能 / DevOps 领域最具影响力的报告。

从2014年开始，每年会出一份，2020年因为疫情的原因没有出，所以到2025年一共有 11 份。这个系列报告详细解释了行业中各类企业的效能水平以及高效能企业如何开展DevOps工作。自2014年首次报告发布以来，就一直延续着这种体系化的风格，提供数据、案例以及许多深入的研究分析结果。报告累计调研了业界36000多名实践者，为我们提供了丰富的学习和实践材料，分享了诸多最佳实践内容，总结了许多宝贵的经验。

# 2. DevData 研发效能基准报告（思码逸）

一份行业调查分析报告，你最看重的是什么？

我想可能的是：数据客观准确、分析方法科学、结论有洞见、可以指引行动等等。

在软件开发效能领域，这样的报告可以说是凤毛麟角。大多数报告都是使用问卷的调研方式，基于被访者主观预估和手工填写的数据收集和整理而成的，常常会出一些数据偏差、客观性不足的问题。但《DevData 研发效能基准报告》是一种新的尝试，我认为也是一种新的突破，实现了以企业客观数据为主体，辅以主观调研的调查方式，结合专业科学分析方法，形成了国内首个研发效能基准分析报告。你可以在报告中获得关于研发交付速率、交付质量、交付能力等多个维度的行业效能客观数据及基线的具体数值，更可以参考报告中挖掘出的高效能研发团队的共性特征，在充分理解自身场景和瓶颈的情况下推进一系列改进尝试。

# 3. Engineering Benchmarks（Linearb公司）

由Linearb公司发布"Engineering Benchmarks"提供了一个比较好的指标体系，这个指标体系兼顾了DORA指标，以及效率、质量、可预测性等指标，在效率方面主要是聚焦代码评审和部署时长两块，其中评审等待时长、评审颗粒度等都直接影响了评审时长，进而影响了周期类指标。

报告中也给出了一些建议，如果大家希望对代码评审进行深入分析，可以作为一个数据参考。

此外提出了Rework和Refactor两个比例指标，其定义就是以21天为界限，如果一段代码21天以上没有修改就认为是legacy code，这当然与我们常规的理解有较大偏差，起码1年以上没碰的代码才是legacy code。当然，我们无需纠结具体数字，其背后体现了对于代码变动的把握能力，编码变动的时长和频率对于很多场景都有指导意义，比如是否需要补充单测，以及代码覆盖率是否充分等等。

第三是两个Accuracy指标，代表了计划的准确性和容量的准确性。对于精英团队来说，做好计划的能力和及时响应变化的能力是并不冲突的。这就好比在做压测的时候要做好容量预估一样，本身也是门玄学，但是通过标准化和数据的积累一定程度上是能有所指导的，这也是数字化洞察可以深挖的一个方向。

# 4. 研发大数据报告（腾讯&阿里）

腾讯在2020-2023年连续发布了3次《研发大数据报告》，阿里巴巴在2020年也发布了一次《研发效能数据知多少》。

从数据统计的角度，我们不建议将其中的数据作为基准参考，因为数据置信度肯定不如DORA、DevData等研究型报告准确和权威，而且这两家大厂为了展示自己的研发实力也难免有刻意PR之嫌。

但我们可以通过这些报告，从指标选择、数据变化上总结出万人级互联网企业对研发效能的价值导向，尤其是哪些指标在持续变好会被认为是研发效能提升的重要表现，并被宣传出来。

因此，我从这个角度，对四份报告做了提炼和一些简单的解读，希望对大家有输入。由于阿里报告对外提供的指标有限，且整体导向和腾讯的报告类似，因此可重点通过分析3份腾讯的报告。
