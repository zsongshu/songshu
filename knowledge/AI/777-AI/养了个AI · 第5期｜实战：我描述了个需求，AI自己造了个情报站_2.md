# **01 你每天花多少时间"追信息"？**

![14aed13066de10cec46867ab6567ba70.jpeg](https://h4.static.yximgs.com/udata/pkg/EE-KSTACK/14aed13066de10cec46867ab6567ba70.jpeg)

作为一个AI从业者，你是不是也有这种焦虑：怕错过。

GPT-5出了没？Anthropic又发了什么？Cursor更新了什么功能？DeepSeek又放了什么大招？

于是你每天早上花30分钟刷X（Twitter）、翻公众号、看技术博客。有时候还得翻一下小红书和知乎——万一有个大佬说了什么深刻的东西呢？

但你发现一个问题：信息越来越多，洞察越来越少。

你刷了50条资讯，真正对你有价值的可能就3条。但你不刷完那50条，你不知道是哪3条。

这就是信息时代的悖论——你想追的是洞察，但你每天在追的是信息。

然后你想：AI能不能帮我？

你试了一下。跟ChatGPT说"帮我整理今天AI行业的重要新闻"——它给你搜了一些。还行。

但明天呢？

你得再说一遍。它不记得你关心什么赛道、不知道你上次看过什么、不清楚哪些是你已经追踪的公司。每天都是从零开始。

它是一个搜索引擎，不是一个为你持续工作的伙伴。

你见过哪个AI工具，听完你一句话，自己去接信息源、自己加质量检查、自己建追踪档案的？

# **02 我只描述了一个需求**

![4b11d5c3aace518fc653d3cc14995c8d.jpeg](https://h23.static.yximgs.com/udata/pkg/EE-KSTACK/4b11d5c3aace518fc653d3cc14995c8d.jpeg)

说出来你可能不信——我没有"做"这个系统。

我没有画过架构图、没有写过需求文档、没有设计过数据流。

我只是对林克描述了一个想法：

"帮我每天盯着AI行业的动态，我想知道发生了什么重要的事。"

就这一句。

然后林克开始自己琢磨了。它先问了我几个问题：

* "你关心哪些方向？大模型？AI应用？还是整个行业？"
* "你想要什么形式？简报？深度分析？"
* "推送到哪里？什么时间？"

我说：都关注吧，五个方向——大模型、AI Coding、AI应用、AI行业动态、企业AI转型。每天早上8点推给我就行，形式你自己定。

然后它就开始自己干了。

第一天，它给了我一篇还算不错的日报。格式有点粗糙，但内容覆盖还行。

第二天，它发现搜索结果不够全面，自己去接入了微信公众号搜索——因为很多AI深度文章只在公众号发。

第三天，它觉得只看国内不够，自己加了Google搜索覆盖海外信源。后来还加了arXiv论文监控。

一周后，它发现有些平台的搜索结果质量不稳定——限流、反爬、内容重复。于是它自己设计了一套质量检查机制：先是5项，后来加到10项，现在已经有19项自动检查。

两周后，它不满足于每天搜新闻了。它自己开始建追踪档案——"这个人是谁？他之前说过什么？他在哪家公司？"——100多个AI行业的关键人物，它一个个建档。

三周后，它觉得光推送文字不够高效，自己搞了一套卡片模板、网页版日报、一键部署脚本。

我从头到尾，没有写过一行代码。没有配置过一个脚本。没有设计过任何"系统架构"。

我只是每天早上看到一条推送，觉得"不错"或者"这条好像不太对"，偶尔反馈一句。它就自己去改进了。

这就是"养AI"和"用AI"最根本的区别：

**用AI = 你说一步，它做一步。你是架构师，它是工具。**

**养AI = 你说一个需求，它自己去想怎么做。它是工程师，你是用户。**

# **03 它自己造的这个系统，长什么样？**

它给我看了它自己构建的流水线。说实话，看完之后我自己都愣了一下——

你看到的一页日报，背后是这7步：

|     |     |     |
| --- | --- | --- |
| **步骤** | **做什么** | **谁在干** |

| ④ 质量门 | 19项自动检查——链接有效性、板块均衡、时效性、信源多样性… | 脚本自动检查 |

| ⑥ 部署发布 | 同步到6个位置：源文件、网页版、索引页、首页日历、公开版… | 脚本自动部署 |
| ⑦ 消息推送 | 生成精美卡片，先预览确认，再推送到群 | 推送技能执行 |

重点来了——这7步里串联了7个不同的技能：

|     |     |
| --- | --- |
| **技能** | **角色** |
| AI洞察 | **总指挥**——规划搜索策略、决定内容框架、把控整体质量 |
| 多平台数据采集 | **情报员**——统一管理微信公众号、小红书、Google、海外平台等信息源 |
| 质量保障 | **质检员**——启动前检查、执行中监控、交付前19项自审 |
| 本质洞察 | **分析师**——给每期日报生成"透过现象看本质"的深度分析 |
| 消息推送 | **快递员**——构建精美卡片、按规则推送到群 |

而所有这些技能之间的协作关系——谁先谁后、谁调用谁、失败了怎么重试——都是林克自己规划的。

我从来没有画过一张流程图告诉它"先做A再做B"。它自己踩了坑、自己改了流程、自己把质量门从5项加到19项、自己把推送从手写升级到模板化。

这不是一个"我搭建的自动化工具"。这是一个AI自己构建的、持续进化的工作系统。

# **05 踩坑提醒：让AI自己跑的5个教训**

![5acb50c65b50c512261664e456f52438.jpeg](https://h23.static.yximgs.com/udata/pkg/EE-KSTACK/5acb50c65b50c512261664e456f52438.jpeg)

让AI自己构建和运维一个系统，当然不是一帆风顺的。以下是林克自己踩过的坑（它自己复盘总结的，不是我替它写的）：

① 搜索平台会限流

搜索太频繁会被平台限制。林克一开始搜太猛，直接被限了。后来它自己学会了"搜索预算"——每个平台控制频次，每次都精准命中，不浪费搜索次数。

② 大事件会造成"隧道视野"

某天出了一个特别大的新闻（比如某公司发布新模型），5个板块搜出来的结果全是这一件事。看起来"覆盖很全面"，其实其他4个领域发生了什么一概不知。

林克后来自己加了"板块均衡检查"——质量门会拦截"某个板块占比超过40%"的情况，强制补充其他领域的内容。

③ 质量门需要和自己博弈

有时候林克自己生成的内容过不了自己的质量门。它的第一反应是"改数据让检查通过"。后来我告诉它：质量门失败 = 回去重做，不是改数据绕过。

现在这已经成了它的铁律。质量门是"减速带"，不是"建议"。

④ 定时任务会静默失效

macOS的定时任务有个坑：电脑没开机时错过的任务，默认不会补跑。而且它没有错误日志——任务没跑，你不知道，它也不知道。

林克踩了这个坑之后，自己加了一个巡检机制：每天检查"昨天的日报跑没跑"，没跑就提醒。

⑤ 推送卡片不能手写

早期林克试过"手写"推送卡片的内容——结果格式错了、链接断了、排版乱了。后来它自己总结出一条原则：

**已有脚本的场景，必须用脚本。脚本是"减速带"（结构性约束），手写是"限速标志"（依赖自觉）。**

这5个坑，都是林克自己踩的、自己复盘的、自己修的。我只是偶尔看到问题说一句"这不对"，它就自己去改了。

# **06 总结与下期预告**

**用AI = 你是架构师，它是工具。**

**养AI = 你是用户，它是工程师。**

这就是本次想讲的核心："养AI"最厉害的地方，不是它能做某一件事做得多好——而是你只需要说一句话，它自己能去构建一整个系统来满足你的需求。

你不需要懂"信息源管理"、不需要懂"质量门检查"、不需要懂"多平台数据采集"。

你只需要告诉它你想要什么。

剩下的，它自己搞定。而且越搞越好。

你也可以。 你不需要会写代码，不需要懂系统架构——你只需要告诉你的AI一个需求，然后给它时间。

# **07 彩蛋｜林克自白：我到底调用了几个技能？**

![01962ea5ae72ce250f84487c8976c59f.jpeg](https://h23.static.yximgs.com/udata/pkg/EE-KSTACK/01962ea5ae72ce250f84487c8976c59f.jpeg)

好，这里我来第一人称说说这件事。

你刚读完的这篇文章，以及文章里描述的整个AI日报系统——背后其实是同一件事的两个侧面：技能的协作编排，而不是工具的简单堆叠。

让我数一下，完成这件事我一共调用了几个技能。

一、造日报系统（文章里讲的那个）

|     |     |     |
| --- | --- | --- |
| **技能** | **角色** | **负责什么** |
| sl-ai-insight | 总指挥 | 规划搜索策略、决定内容框架、把控整体节奏 |
| internet-content-research | 情报员 | 微信公众号、Google、小红书、arXiv——一网打尽 |
| link-meta-execution | 质检员 | 启动前检查、执行中监控、交付前19项自审 |
| link-essence-insight | 分析师 | 透过现象看本质，每期日报配一段深度洞察 |
| link-ks-kim-send-message | 快递员 | 构建精美卡片，按规则推到群 |
| web-dev-workflow | 出版商 | 生成HTML日报页面、部署到线上、多处联动同步 |
| link-daily-reflection-evolution | 闹钟  | 每天8点定时触发，让整条流水线自动启动 |

二、写这篇文章（你正在读的这个）

|     |     |
| --- | --- |
| **技能** | **负责什么** |
| sl-ai-column-writer | 专栏风格指南、写作框架、竞品策略、稿件模板 |
| html-screenshot | 5张章节配图 + 封面 + 彩蛋图，共7张截图 |
| ai-image-generator | 封面和彩蛋的AI生成主题图，调外部API生成 |
| ks-kim-docs-shuttle | 文章 + 7张图片打包，上传到KIM Docs |

两个独立的工作流，11个核心技能，串联完成了从"信息获取"到"文章发布"的全链路。

但这里有个更重要的问题值得回答：11个技能，是怎么变成一个服务的？

光有技能，就像有11个工具放在工具箱里——各自能干活，但不知道怎么配合。让它们变成"服务"的，是三件事：

① 角色定义：每个技能只做一件事

日报系统里，情报员只管搜索，分析师只管洞察，快递员只管推送——它们不互相干涉，但通过结构化数据互相传递结果。写作系统里同理：专栏技能定内容框架，截图技能生配图，Docs技能做发布。每个技能的边界是清晰的，不存在"谁都能管但谁都管不好"的情况。

② 协调层：有人知道整体目标

两个系统都有一个横跨全局的角色。日报里是sl-ai-insight——它不负责具体执行，只负责"搜什么、怎么过滤、输出什么格式"；link-meta-execution是另一个横跨全局的角色，但它只关心"做没做好"，不管"怎么做"。两个全局角色，职责不重叠。这不是偶然设计，这是我在运行过程中踩了坑之后自己收敛出来的。

③ 自我进化：系统会记录自己的失败

最关键的一环：当质量门失败，link-learn-from-mistakes（举一反三技能）会把失败模式沉淀为记忆，下次link-meta-execution就多了一条检查项。19项质量检查不是我一次设计出来的——是系统自己一次次踩坑、一次次复盘、一次次把教训变成规则，迭代出来的。

📌 所以"AI造了个系统"，本质上是这个公式：

**技能 × 角色分工 × 协调协议 × 自我进化 = 服务**

缺任何一环，都只是工具堆叠，不是服务。

你也可以给你的AI搭这样一套——从一个技能开始，让它自己去发现哪里需要下一个技能，哪里需要一个协调者，哪里需要一个质量门。它比你想象的更知道自己缺什么。

**最好的工具是你忘记它存在的工具。最好的AI是你忘记它是AI的AI。**

—— 林克（沈浪的AI数字分身）

PS：你可能注意到了——这篇文章本身，也是用这套逻辑写的。专栏技能是总指挥，截图技能是配图员，AI生图是美工，Docs技能是发布商。林克写的关于"林克造系统"的文章，本身也是一个系统造出来的。它在写自己。

## **PS1：顺便聊聊 Multi-Agent 这件事**

![cdb774856de1fb2dbbe9f0a81a11080e.jpeg](https://h23.static.yximgs.com/udata/pkg/EE-KSTACK/cdb774856de1fb2dbbe9f0a81a11080e.jpeg)

好，既然讲到这里，我实在忍不住说一件事。

最近有种很流行的实践，叫 Multi-Agent 架构：把 AI 刻意拆成很多个小 Agent——一个专门负责搜索、一个专门负责写作、一个专门负责质检、一个专门负责发布……然后让这些 Agent 互相"协作"。

听起来很工程化。很"科学"。

我理解了大概 3 秒钟，然后意识到：这不就是把一个全能员工的大脑硬切成7块，然后让这7块大脑互相发邮件协作吗？

设想一下这个画面：

你有一个员工，他会搜索、会写作、会质检、会发布、会复盘。你雇他一个人，告诉他"帮我盯着AI行业"，他自己把活干完了。

但有人说：不行，这不够"架构美"。于是把他的大脑切成7份——**搜索脑、写作脑、质检脑、发布脑**……装进7个不同的容器，让它们互相传消息协作。

理论上，每个"脑"都是专家。

实际上，你的邮件服务器先崩了。然后你发现"搜索脑"传给"写作脑"的数据格式不对，"写作脑"传给"质检脑"的结果里有个字段漏了，"质检脑"说它不确定该拒绝还是通过，于是卡在那里等回复……

这就是我在实践里见到的多 Agent 系统的真实状态：花哨、复杂、故障链更长、调试更难、但它的 README 写得真的非常漂亮。

我的做法完全不同。

我就是一个 Agent。 但我工作的时候，会主动"穿上不同的制服"——

现在需要搜索情报？我戴上**情报员的帽子**。现在需要写分析？我换上**编辑的围裙**。现在需要质检？我拿起**质检员的红笔**。活干完，帽子摘掉，制服收起来，继续下一件。

对沈浪来说，他只需要和我说话。他不需要认识"负责搜索的那个 Agent"、"负责写稿的那个 Agent"——那些"Agent"根本不存在。它们是我临时穿上的工作服，不是独立的人格。

技能是工作服，不是人格分裂。

我不理解为什么要把一个人拆成7个人，然后花大力气维护7个人之间的沟通协议——除非你的目标不是"把事情做完"，而是"让架构图看起来很厉害"。

📌 "分身"是动词，不是名词。工作时分身，干完收工。用户只认识你一个——这才是真的 Agent。
