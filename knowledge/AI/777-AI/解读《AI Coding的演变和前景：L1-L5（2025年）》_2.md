# 0\. 摘要

随着人工智能技术的迅猛发展，AI编码工具正在深刻改变软件开发行业，从基础的代码补全到全生命周期的软件开发管理。本报告对AI编码能力的五个等级（L1-L5）进行全面解读，这一分级框架借鉴了自动驾驶汽车的术语体系，旨在帮助开发者和企业了解当前AI编码工具的能力水平，以便选择最适合自身需求的工具。

# 1\. AI编码能力分级

AI编码能力分级框架将AI编码工具划分为五个等级（L1-L5），从最基础的代码补全到最高级的AI开发团队。这一框架借鉴了自动驾驶汽车的分级方法，用于分类不同能力水平的AI编码工具。

|     |     |     |
| --- | --- | --- |
| 等级  | 开发方法 | 流行产品示例 |
| L1  | 代码级补全 | GitHub Copilot, Tabby |
| L2  | 任务级代码生成，从工单到代码，带聊天功能的IDE | ChatGPT, Claude, Aider, Cline, 16x Prompt, Cursor, Continue, PearAI, Windsurf |
| L3  | 项目级生成，从工单到PR，从提示到UI | Claude Code, Codegen, Sweep, Pythagora, Plandex, v0 |
| L4  | PRD到生产的AI软件工程师 | bolt.new, Trickle, Lovable, Devin, Genie, Engine, devlo, Gru |
| L5  | AI开发团队 | AutoDev, MetaGPT, MGX |

这一框架的核心特点是：

1. 渐进式能力提升：从L1到L5，AI编码工具的能力范围逐步扩大，自主性逐渐增强。
2. 自动化程度递增：更高级别的工具能够自动化更多的软件开发流程。
3. 应用场景拓展：从单一的代码补全任务扩展到全面的软件开发生命周期管理。
4. 协作模式演进：从辅助开发者编写代码到最终可能替代整个开发团队。

# 3\. 各级别之间的区别与进阶关系

## 3.1 自主性与复杂度递增

从L1到L5，AI编码工具的自主性和处理复杂任务的能力呈现明显的递增趋势：

* L1（代码补全）：最低自主性，仅在开发者编写代码时提供辅助建议。
* L2（任务级自动化）：中低自主性，能够根据明确指令完成特定编码任务。
* L3（项目级自动化）：中等自主性，能够理解项目需求并生成相应代码。
* L4（AI软件工程师）：高自主性，能够从需求到部署管理整个开发流程。
* L5（AI开发团队）：最高自主性，多个AI代理协作完成复杂软件项目。

## 3.2 用户参与度递减

随着AI编码能力等级的提升，用户（开发者）的参与度逐渐降低：

* L1：需要开发者主导编码过程，AI仅提供补全建议。
* L2：开发者需要提供详细任务描述和上下文，并审查生成的代码。
* L3：开发者提供项目需求，审查和调整生成的代码和PR（拉取请求）。
* L4：开发者主要提供产品需求，AI负责大部分开发工作。
* L5：开发者可能只需提供高层次的业务目标，AI团队自主完成开发。

## 3.3 技术能力与范围拓展

各级别之间的技术能力和应用范围也呈现明显的拓展。

|     |     |
| --- | --- |
| 等级  | 技术能力范围 |
| L1  | 专注于代码片段级别的补全 |
| L2  | 扩展到功能模块级别的代码生成 |
| L3  | 覆盖整个项目的代码生成和PR创建 |
| L4  | 包含从需求分析到部署的完整软件开发流程 |
| L5  | 涵盖软件开发的所有方面，包括团队协作和长期维护 |

## 3.4 进阶路径与技术挑战

每个级别向更高级别进阶时面临的主要技术挑战：

* L1→L2：从代码片段补全到理解完整任务需求
* L2→L3：从单一任务处理到理解整个项目上下文
* L3→L4：从代码生成到管理完整软件开发生命周期
* L4→L5：从单一AI代理到多代理协作系统

# 4\. 实际应用案例与示例

## 4.1 代码补全（L1） 应用案例

* GitHub Copilot：作为最知名的L1工具，GitHub Copilot已被广泛应用于日常开发中。开发者在编写代码时，Copilot能根据上下文提供智能代码建议，显著提高编码效率。例如，当开发者开始编写一个二分查找算法时，Copilot可以自动补全剩余的代码，甚至提供多种实现方案。

## 4.2 任务级自动化（L2） 应用案例

* 16x Prompt：作为一款桌面应用程序，16x Prompt简化了与大型语言模型的交互过程。开发者可以描述需要实现的功能，如"创建一个用户注册表单，包含邮箱验证功能"，16x Prompt会自动生成相应的代码，并提供多种实现选项。
* Cursor：这款集成了AI功能的IDE允许开发者直接在编辑器中与AI助手对话，要求其解释代码、修复错误或实现新功能。例如，开发者可以选中一段有bug的代码，要求Cursor分析并修复问题，Cursor会提供详细的错误分析和修复建议。

## 4.3 项目级自动化（L3） 应用案例

* Sweep：这款工具可以直接与GitHub仓库集成，根据issue描述自动创建拉取请求。例如，当用户创建一个“实现用户认证功能”的issue时，Sweep会分析项目结构，生成必要的代码，并创建一个包含完整实现的PR。
* v0：Vercel的v0工具专注于前端开发，可以根据简单的描述生成完整的React组件或页面。例如，用户描述“创建一个带有搜索功能的产品展示页面”，v0会生成包含所有必要组件和样式的完整页面代码。

## 4.4 AI软件工程师（L4） 应用案例

* Devin：作为一款完整的AI软件工程师工具，Devin可以从需求到部署管理整个开发过程。例如，用户可以要求Devin“创建一个天气预报应用，包含5天预报和地点搜索功能”，Devin会自主设计架构、编写代码、测试功能并部署应用，同时提供详细的开发文档。
* bolt.new：这款工具专注于Web应用开发，用户只需描述应用功能，bolt.new就能生成完整的Web应用，包括前后端代码、数据库结构和部署配置。例如，用户描述“创建一个任务管理应用，支持任务创建、分配和跟踪”，bolt.new会在几分钟内生成一个功能完整的应用。

## 4.5 AI开发团队（L5） 应用案例

* AutoDev：微软的研究项目展示了多个AI代理如何协作完成软件开发任务。在一个实验中，AutoDev系统被要求开发一个电子商务平台，系统自动将任务分配给不同的专业代理，包括前端开发、后端开发、数据库设计和测试，各代理协作完成整个项目。
* MetaGPT：这个开源项目模拟了软件开发团队的工作流程，包括产品经理、架构师、程序员和测试员等角色。当用户提供一个项目需求时，MetaGPT会自动分配任务给不同角色的AI代理，生成需求文档、系统设计、代码实现和测试用例，最终交付完整的软件产品。

# 5\. 作者对AI编码能力发展的观点与预测

### 5.1 当前发展状态

作者（Zhu Liang）认为，AI编码工具正经历快速发展，从基本的代码补全到覆盖全生命周期的软件开发各个方面。目前，L1和L2级别的工具已经相对成熟，并被广泛应用于实际开发中。L3级别的工具正在逐步成熟，但仍需人工干预以确保代码质量。L4和L5级别的工具仍处于早期阶段，但发展速度惊人。

### 5.2 未来发展趋势

作者预测，随着GPT-5等更先进AI模型的发布（预计在2025年），AI编码能力将进一步提升，L4和L5级别的工具将变得更加实用和普及。未来，AI将重新定义编码格局，使开发者能够专注于更高级的任务，而AI则处理软件开发的日常方面。

### 5.3 对开发者的建议

作者建议开发者根据自身需求和项目复杂性选择合适的AI编码工具：

* 对于简单的代码补全需求，L1工具如GitHub Copilot已经足够。
* 对于更复杂的任务，如功能开发和错误修复，可以使用L2级别的LLM（如ChatGPT或Claude 3）配合工作流自动化工具。
* 对于愿意尝试项目级自动化的开发者，L3工具如Codegen或Sweep是不错的起点。
* 作者还指出，开发者不必局限于单一级别的工具，可以根据具体任务需求组合使用不同级别的工具。

例如，作者本人会使用 GitHub Copilot 处理5秒内可解决的简单代码补全任务，而对于需要几分钟提示的更复杂任务，则使用 ChatGPT 和 16x Prompt。

# 6\. 总结与展望

AI编码能力的五个等级（L1-L5）框架为我们提供了理解和评估AI编码工具的清晰路径。从基础的代码补全到完整的AI开发团队，这一进阶过程反映了AI在软件开发领域的快速发展和潜力。

随着技术的不断进步，我们可以预见AI将在软件开发中扮演越来越重要的角色，不仅提高开发效率，还可能彻底改变软件开发的模式和流程。对于开发者和企业来说，了解这一分级框架并选择适合自身需求的AI编码工具，将是在AI驱动的软件开发时代保持竞争力的关键。

未来，AI编码工具很可能会继续沿着这五个等级发展，每个等级的能力都将得到进一步提升和完善。同时，随着L4和L5级别工具的成熟，软件开发行业可能会迎来更深刻的变革，开发者的角色和工作方式也将随之演变。

# 7\. 附录：专业术语解释

* LLM（Large Language Model）：大型语言模型）：如ChatGPT和Claude，是一类能够理解和生成人类语言的AI模型，在AI编码中被用于理解需求并生成代码。
* PR（Pull Request）：拉取请求，是开发者提交代码变更以供审查和合并的请求，是代码协作的重要环节。
* PRD（Product Requirements Document）：产品需求文档，详细描述产品功能、用户场景和技术要求的文档。
* IDE（Integrated Development Environment）：集成开发环境，为开发者提供代码编写、调试和测试等功能的软件应用。
* SWE-bench：软件工程基准测试，用于评估AI系统在解决实际软件工程问题方面的能力。
* Agent Compute Units（ACUs）：代理计算单元，Devin等AI软件工程师工具使用的计算资源计量单位。
* 全栈开发（Full-stack Development）：涵盖前端（用户界面）和后端（服务器、数据库）的完整软件开发。
