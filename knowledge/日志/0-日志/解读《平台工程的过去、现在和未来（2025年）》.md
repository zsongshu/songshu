# 1\. 平台工程是什么？

## 1.1 什么是平台工程

简而言之，可以这么理解：平台工程通过产品方法实现了一定的开发人员自助式服务（包括工具、最佳实践），可将开发人员完成日常任务遇到的阻力降到最低。减轻开发人员的认知负担的同时，还保留了一定的自由度。

|     |     |
| --- | --- |
| 标准概念定义 | 图示  |
| 按Gartner的定义：<br><br>* 平台工程是关于构建和运行内部自助服务平台的学科，每个平台是一个层，由专门的产品团队创建和维护，通过对接不同的工具和流程支持用户的具体需求。<br>* 按平台工程社区的发起人Luca Galante在[<u>platformengineering.org</u>](http://platformengineering.org/)对平台工程的描述的定义：平台工程是一门设计和构建工具链与工作流的学科。这些工具链和工作流可以为云原生时代的软件工程组织提供自助服务功能。平台工程师提供集成化产品，通常称为“内部开发平台（Internal Developer Platform - IDP）”，可以涵盖应用程序整个生命周期的所有操作需求。 | ![resize,w_2000,m_lfit,limit_0](https://static.yximgs.com/udata/pkg/EE-KSTACK/037cb247ba6919796e9ae6a49a5219a8.png?x-oss-process=image/resize,w_2000,m_lfit,limit_0) |

## 3.2 演进路径：「AI x 平台工程」双螺旋式进化，迭代出下一代“智能研发平台”

### 2021年以前，敏捷与DevOps时代：各垂直领域单点工具崛起，尤其是CICD

* 个体效率 ：工作逐步从线下到线上，效率提升
* 整体效率 ：研发各环节仍然割裂，缺少标准化和数据

![ad24054623e8f396f4a84aac8d2a5772.png](https://static.yximgs.com/udata/pkg/EE-KSTACK/ad24054623e8f396f4a84aac8d2a5772.png)

### 2022-2024年，研发效能时代：串联流程的「一站式研发平台」出现、效能度量崛起

* 个体效率 ：由于被迫迁移到新的串联平台，标准多、卡点多、产品缝合度高，日常工作体验、效率反而下降。
* 整体效率 ：建设「研发流程」类的功能，开始串联从需求到发布，流程更标准、各环节增加卡点提升质量、通过标准化数据洞察问题并驱动改进。

![ba10c635144f9827a496356a82e07059.png](https://static.yximgs.com/udata/pkg/EE-KSTACK/ba10c635144f9827a496356a82e07059.png)

### 2022-2025年H1，智能研发时代：编码环节，AI编程崛起，非编码环节，均在AI化探索中

* 个体效率：AI编程IDE开始替代原有IDE，编码效率提升；非编码环节的工具陆续“Agent”化，但用户复杂度并为降低，反而需要学习的东西更多了。

![resize,w_2000,m_lfit,limit_0](https://static.yximgs.com/udata/pkg/EE-KSTACK/30dcc5794c04d04c99d4740a25d56777.png?x-oss-process=image/resize,w_2000,m_lfit,limit_0)

### 2025H2-未来，智能研发时代：融合“AI”和“平台工程”2个理念的“智能研发平台”会应运而生，分阶段逐步解决个体效率和体验问题

![9eb8c613f4e773d285aace7258c68284.png](https://static.yximgs.com/udata/pkg/EE-KSTACK/9eb8c613f4e773d285aace7258c68284.png)

## 3.3 写在最后

目前，业界正常经历AI Coding的“百团大战”，还没有一家公司，能完全实现“AI x 平台工程”这个面向未来的解决方案。但相信在未来1-2年内，以这个理念为核心的“下一代智能研发平台”会真正出现，并带着成功的企业案例、产品与解决方案，席卷整个研发效能行业，让我们拭目以待。
