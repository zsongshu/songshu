### **源文档链接：**[关键指标术语表-终版](https://wiki.corp.kuaishou.com/pages/viewpage.action?pageId=19630927)

### **文档简介**

本文档列举重点用于决策的指标，包含最终优化指标，和关键事件和关键质量指标，供与数据打交道的同学参考使用。
特别提醒，本文列举的重点指标为公司通用指标，数据指标准确性要特别重视，用于汇报和讨论时切记两点：

* **多方核对：基于不同数据源的相关数据Double-check,避免误解**
* **常用指标一定不要轻易赋予新的定义：人们已经比较接受常用指标定义，比如留存等等，轻易赋予其新的含义容易在观众侧产生较大误解**

### **文档详情**

|     |     |     |

| #### 重要结果指标/优化目标 |     |     |
| **指标名称** | **定义描述** | **备注/应用举例** |
| DAU | 日启动设备数：基于设备计算（不考虑用户是否登录账号），统计周期内将启动设备ID去重计数 | 设备A在8月1日的8点和21点均有启动记录，计算8月1日DAU时只计算一次 |
| MAU | 月启动设备数：基于设备计算（不考虑用户是否登录账号），统计周期内将启动设备ID去重计数 | 设备A在8月1日和8月30日均有启动记录，计算8月MAU时只计算一次 |
| 人均使用时长 | 设备日均平均时长：APP日总使用时长/日启动设备数 | 8月1日APP使用总时长为6100w分钟，8月1日启动设备100w，则人均使用时长为6100w / 100w = 61分钟 |
| 登录用户数 | 基于登录用户ID计算，Anti-spam后数据，统计周期内将用户ID去重计数 | 8月1日总登录用户数1000w，按照8月1日的spammer判定规则spammer用户70w，则8月1日Anti-spammer登录用户数（1000w-70w）= 930w |
| 新增设备 | 基于启动设备ID计算，统计周期内将首次出现的设备ID去重计数 | 设备ID为 X 的设备8月1日首次出现在平台上，则该设备记为8月1日的新增设备 |
| 新增注册用户数 | 基于首次出现用户ID计算，Anti-spam后数据，统计周期内将用户ID去重计数 | 8月1日总新增用户100w，其中20w被判定为spammer，则新增注册用户数为(100w-20w)=80w |
| #### 关键事件及质量指标 |     |     |
| **指标名称** | **定义描述** | **备注/应用举例** |
| show | 服务端记录的作品曝光次数 | 作品批量下发给用户，全部算server show，<br>为保证体验，服务端会预取下一批作品预备下次推送给用户，预备作品不算show |
| real show | 客户端记录的作品曝光次数，在客户端渲染成功即为曝光 | 在客户端屏幕展示的show，称为 real show |
| click | 根据用户ID去重的作品点击次数 | 服务端记录的客户端实时api请求，某用户对同一个视频click多次，算1次click |
| like | 根据用户ID去重的用户点赞次数 | 服务端记录的客户端实时api请求，某用户对同一个视频点赞多次，算1次点赞 |
| forward | 根据用户ID去重的用户分享次数 | 服务端记录的客户端实时api请求，某用户将同一个视频通过多渠道转发，算1次转发 |
| follow | 根据用户ID去重的用户关注次数 | 服务端记录的客户端实时api请求，某用户对同一个用户关注1次，取关1次，再关注1次，算1次关注 |
| hate | 根据用户ID去重的用户点击减少此类作品的次数 | 服务端记录的客户端实时api请求，同一个用户对同一个作品做了多次减少此类作品操作，算1次hate |
| watch | watch默认为follow |     |
| ctr | click through rate，点击率，等于click/show |     |
| ltr | like through rate，点赞率，等于like/click |     |
| ftr | forward through rate，转发率，等于 forward/click |     |
| wtr | follow through rate，等于 follow/ click，以区分forward through rate概念 |     |
| htr | hate through rate，讨厌率，等于hate/show |     |
| clctr | 取消点赞率，等于unlike/click |  |
| cwtr | 取消关注量，等于unfollow/click |  |
| sample count | 在发现页/同城页/关注页上real show展示过的photo数，目前主要关注发现页 |     |
| 留存率相关重要概念 |     |     |
| **指标名称** | **定义描述** | **应用举例** |
| 新增留存 | 对应有新增设备、新增登录用户、新增作者、新增主播、新增付费用户、新增功能使用，对应的后续留存情况<br>常关注次日留存率、7日留存率、30日留存率、次月留存率 | 涉及用户数据，做Anti-spam操作 |
| （存量）活跃留存 | 主要针对非新增且活跃的存量设备、登录用户、作者、主播、付费用户，看其后续留存情况<br>常关注次日留存率、7日留存率 | 涉及用户数据，做Anti-spam操作 |
| 新增设备留存率 | 新增设备，在统计周期内仍然活跃的比例，常关注次日留存率、7日留存率、30日留存率<br>以次日留存率为例：当日新增设备中，在第2日仍然打开快手App的设备比例<br>以7日留存为例，当日新增设备中，在第8日仍然打开快手App的设备比例 | 举例：某日150w个新设备中，第2天这150w用户中依然有120w打开快手App，则新设备次日留存率为120w/150w=80% |
| 活跃设备留存率 | 当日活跃设备中（包含新增设备和存量设备），在统计周期仍然打开快手App的设备比例 | 举例：某日5000w个活跃设备登录快手App，第2天这5000w设备中仍有4600w登录快手App，则次日留存率为4600w / 5000w = 92% |
| 注册率相关重要概念 |     |     |
| **指标名称** | **定义描述** | **应用举例** |
| 新增设备当日注册率 | 当日新增设备中，关联老账户或者新账户的设备占比，去除未关联垃圾账号设备后计算<br>即：（当日关联老账号设备+当时关联新账号的设备）/ (新增设备总数-新增垃圾设备总数） | 举例：某日新增设备155w，关联垃圾账号设备5w，剩余的150w设备中30w关联新账户，80w设备关联老账户，40w设备未关联账户，则：<br>全量设备当日注册率=（30w+80w）/ (155w-5w)=73.3% |
| 新增设备当日全新注册率 | 当日新增设备中，关联新账户的设备占比，去除未关联垃圾账号设备<br>关联新账号设备数/(新增设备总数-新增垃圾设备总数) | 举例：某日新增设备155w，关联垃圾账号设备5w，剩余的150w设备中30w关联新账户，80w设备关联老账户，40w设备未关联账户，则：<br>全量设备当日全新注册率= 30w / (155w-5w)=20% |
| 未关联老账号全新设备注册率 | 当日新增设备中，去除关联老账号设备和垃圾设备后，关联新账户的设备占比<br>关联新账号设备数/(新增设备总数-新增垃圾设备总数-老设备总数) | 举例：某日新增设备155w，关联垃圾账号设备5w，剩余的150w设备中30w关联新账户，80w设备关联老账户，40w设备未关联账户，则：<br>全量设备当日全新注册率= 30w / (155w-5w-80w)=42.9% |
| 封禁相关重要概念 |     |     |
| **指标名称** | **定义描述** | **应用举例** |
| 封禁  | 针对账户操作，主要针对用户账户的永久封禁，封禁后用户不能点赞、关注、评论、私信、发视频、直播、进直播、被搜索，可申请解封 |     |
| 直播封禁 | 针对直播权限，分A/B/C类处罚：A类永久封禁（可申诉）、B类限时封禁1~9天，第10次永久封禁、C类警告1次弹窗，2次关播，3次封禁1天 |     |
| 社交封禁 | 针对账户操作，针对 spammer 的机器算法封禁，不能发私信、发评论、关注、点赞、直播、举报、进入直播间，可h5解社交封禁 |     |
