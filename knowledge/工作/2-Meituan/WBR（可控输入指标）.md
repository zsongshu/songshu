# WBR（可控输入指标）



|     |
| --- |
| 运营计划（OP）确定后，通过（周/月/季度）业务回顾（Weekly/Monthly/Quarterly Business Review, WBR/MBR/QBR），可以对指标和团队目标进行监控和追踪，从而检视经营情况。WBR、MBR和QBR的侧重点不同。一般而言，WBR是每周对业务输入输出指标的快速扫描，只有数据图表，聚焦讨论异动指标。MBR/QBR是对整月或整季度经营目标达成情况的深入分析，常见形式是6页纸加附表，会上复盘周期内的得失、分析没达到的目标、制定短期策略。 |
| 什么是可控输入指标？<br>可控输入指标是**衡量能带来预期业务结果的业务动作**的指标或者说驱动业务增长的业务动作的指标。<br>1）**可控的、对输出影响最大的**。<br>2）相比输出指标（如订单量、市占率），**更加以客户为中心**，更加关心客户体验和客户价值。<br>3）**揭示原因，让人更早地发现关键信号**。对输入做功是拿到业务结果的重要原因，通常发生在业务结果产生之前。因此关注可控输入指标，可以帮助我们更早发现信号，比如用户体验是否在改善，业务是否在健康有序的节奏上，对输入做功的策略是否有效，等等。<br><br>最典型的应用就是亚马逊的飞轮，更多的商家提供更丰富的商品选择，产生更好的体验，吸引更多的流量，进而又带来更多的商家，形成正循环，推动业务持续增长。这里的商家、商品选择、体验、流量就是驱动业务增长的关键输入，关键输入指标是衡量这些关键输入发展水平的一系列指标，关键可控输入指标则是指其中那些我们可以通过做功改善的指标。 |
| WBR机制的三个关键要素<br>WBR的核心内容是数据分析。统计学家、质量控制专家Donald Wheeler（他是统计过程控制这种质量控制方法的代表人物，“PDCA循环”提出者Deming的学生，对亚马逊早期的指标体系建设、WBR机制设计有直接影响）认为**数据分析有三个关键成功要素：****1.****必须选择和掌握正确的数据**。**2.****数据需要恰当的呈现方式**。**3.** **应该采用简单有效的分析方法**。<br>**1.** **应该如何选择和获取正确的数据？**<br>**1****）注重输入分析，迭代输入指标。**在WBR材料中，输出指标篇幅占比通常<10%，其他都是可控输入指标。相应地，会议的绝大部分时间用来讨论可控输入指标，而不会脱离输入指标来讨论输出指标的变化。<br>**2****）保留足够的颗粒度，用****“****输入指标树****”****理念确保指标可以下钻，同时不对数据做过度聚合。**WBR的基础是业务的完整“输入指标树”。WBR保留足够的细节信息十分关键。如果数据被过度聚合，比如把过多不同产品形态、不同品类、不同区域市场的数据简单加总起来，数据就失去了其背景和有用性，不能体现出具体哪里有问题。上一层级的运营单元做WBR时，**不是对下一层的各团队的指标做直接加和，而往往是抽取材料中重要页面、挑选其中重要的指标汇总起来并列呈现**。<br>**3****）看业务****“****端到端****”****、全链条的指标，****“****连点成线****”****能揭示孤立看某一环节时不易看到的问题，从而带来指标体系的迭代。**有两种情形：**一是单个环节的指标变化反映和提示其他环节的缺漏，应该补齐。二是某个环节指标的局部优化给其他环节指标甚至全局造成负面影响，应该改掉这个指标。**<br>**2.** **如何恰当地呈现数据？**<br>**应使用较长时间周期的时间序列数据。使用折线图，把近****6****周和****12****个月的数据放在一张图上，用两条线分别代表当年和去年**。图的好处在于非常直观、趋势一目了然，能节省阅读时间。但也有少数情况图的效果不如表（比如一个指标包含很多子指标，需要放在一起相互比较，在图上列示过多条线太拥挤），这时可以采用图+表的形式增加信息密度。<br>**3.** **应该用什么分析方法？**<br>在获取和呈现数据后才进入到真正的分析阶段，要做3件事：**1****）找到指标变化中的****“****信号****”****，****2****）分析变化背后的根本原因，****3****）针对根本原因制定行动计划。**<br>**1****）找****“****信号****”****：数据的变化（****variation****）是不可避免的，必须把变化中的****“****噪音****”****（****noise****）和****“****信号****”****（****signal****）区分开。**“噪音”是常规的、正常的变化，**“****信号****”****是例外的、根本的变化，包括超出正常范围的变化或持续恶化****/****改进的趋势。只需要分析并用行动响应****“****信号****”****，**而不必分析、响应“噪音”。**过滤掉****“****噪音****”****、找到****“****信号****”****是指标负责人的责任。**<br>**2****）根因分析：**指标负责人应在会前深入分析“信号”背后的根本原因。**关键步骤是先描述问题和影响，再用****5 Whys**——在一个问题上至少连问5次why层层下钻，**直到问到了根本原因，且要明确该原因是否可以被提前发现。除了负责人自身的业务经验外，分析也可以得到数据系统的帮助**。<br>**3****）定行动计划：**承接上述1）2），指标负责人应该对**针对根因去说明有什么应对方案。**对于**负面****“****信号****”****，有什么改善计划？**不论内因还是外因都应该有改善计划，比如问题是恶劣天气造成的，那下一次再遇到相同情况时我们的应对方法会有什么改进？对于**正面****“****信号****”****，如何保持或****“****双倍下注****”****（****double down****）扩大积极的趋势？** |
| WBR会议怎么运营？<br>**会前**：应把指标负责人的名字标在指标上。他们在会前1-2天拿到数据，预先看自己负责的指标，找出“信号”，准备好清晰的根因分析和行动计划。商分团队也可以初步圈出他们看到的“信号”，帮助讨论更聚焦。<br>**会中**：WBR是向业务的负责人汇报的会议，参会人一般是业务负责人\-1和部分负责某些指标的\-2层。WBR的时长通常在1-3小时之间。业务负责人通常自己主持会议。常见的流程是：把材料投屏出来一页页快速过，由指标的business owner讲有“信号”的指标，业务负责人可以随时发问。因为会议时间非常紧凑，绝大部分的提问来自业务负责人，其他参会人除非发现了重要问题被遗漏，否则不会主动发问。<br>**会后**：如果有会上没有解释清楚的问题，指标的owner会记to-do回来做进一步分析，之后通过邮件把结论告诉相关方。也有团队会在WBR材料最前面一页反馈上次WBR的跟进事项。 |
