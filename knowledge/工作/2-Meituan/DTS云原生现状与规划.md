# DTS云原生现状与规划

|     |     |
| --- | --- |
|  | 1. 背景信息：<br>	1. 云原生 = 微服务 + 容器化 + devops + **持续交付**<br>	2. k8s = docker + **声明式部署** （docker专注单个容器的生命周期管理、k8s专注于集群的管理）<br>2. 期望解决的问题<br>	1. 提升效率：云原生架构下，服务发布做到了标准化和自动化，加速了部署、变更、运维速度<br>	2. 降低成本：优化资源使用和减少手动运维，降低机器成本和运维成本<br>3. 已经做了哪些事，以及产生的收益<br>	1. 100%迁移k8s<br>		1. 集群编排配置化：包含镜像、容器规格、副本数、机房分布、依赖检查、健康检查等，做到了所见即所得<br>		2. 集群运维白屏化：DTS平台一键完成（包含部署、发布、扩所容、改配）<br>		3. 自定义超售比：2.5倍 -> 3.125倍<br>		4. 收益：<br>			1. 资源池CPU分配率：37% -> 74%<br>			2. 单个任务使用CPU：2.9核 -> 2.5核，减少12.3%（预计24年底再减少30%，到 1.8核）<br>			3. 单集群升级时间：5分钟 -> 10s<br>			4. 运维效率/可靠性提升：<br>				1. 手动操作减少，运维方式转变，由DTS平台、Avatar、Plus等平台跳转 -> DTS平台配置运维计划（解决了误操作的可能性，集群升级投入降低）<br>				2. 机器故障情况下，k8s迁移故障节点并收敛的期望的状态（机房裁撤、资源池腾挪效率提升）<br>	2. 存算分离改造<br>		1. 解决磁盘存储瓶颈，磁盘不足告警降至0<br>		2. 存储15天Binlog，具备承接flashback能力，已开始承接DBS数据修复工作<br>4. 计划做哪些事，以及期望产生的收益<br>	1. 弹性，预留资源 -> 按需<br>	2. 多副本存储 -> 单副本存储<br>	3. 按Region拆分MKE集群 -> 按AZ拆分MKE集群<br>5. 需要哪些帮助<br>	1. 补齐基本能力：如IO限流<br>	2. 解决Agent问题：轻容器不具备如断网等故障能力、不支持火焰图<br>	3. 保持运维方式不变：例如sidecar变更 |
