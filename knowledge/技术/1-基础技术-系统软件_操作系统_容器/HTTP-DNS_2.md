# HTTP-DNS

HTTP-DNS（也称为HTTPDNS）是一项创新的域名解析技术，它通过HTTP/HTTPS协议直接向专用的DNS服务器查询，完美避开了传统DNS解析链条中的风险环节，从根本上解决了本地DNS劫持等问题。下面这个表格清晰地展示了HTTP-DNS与传统DNS的核心区别。

|     |     |     |
| --- | --- | --- |
| 特性维度 | **传统DNS** | **HTTP-DNS** |
| **协议与端口** | UDP/TCP, 端口53 | HTTP/HTTPS, 通常端口80/443 |
| **查询路径** | 应用 → 本地DNS → 递归查询… | 应用 → HTTP-DNS服务端（直接HTTP请求） |
| **安全性** | 低，明文传输，易被劫持 | 高，可使用HTTPS加密，防劫持 |
| **调度依据** | 本地DNS服务器的IP地址 | 客户端的真实IP地址 |
| **控制力** | 弱，受制于运营商本地DNS | 强，解析策略自主可控 |

### **🔧 HTTP-DNS 的工作流程**

HTTP-DNS的实现依赖于客户端集成SDK，其工作流程是一个高效的闭环系统。

1. **初始化与缓存检查**：当应用程序（如手机App）启动时，其内置的HTTP-DNS SDK会首先查询本地的缓存。如果目标域名的IP地址存在且未过期（TTL有效），则直接使用该IP，实现“0毫秒”解析。
2. **发起HTTP(S)请求**：如果缓存无效，SDK会选择一个可用的HTTP-DNS服务端IP（通常由服务商提供多个），通过标准的HTTP/HTTPS协议发送请求。请求中会包含要解析的域名，有时还会带上客户端的真实IP以便更精准的调度。
3. **服务端智能调度**：HTTP-DNS服务器收到请求后，能直接看到客户端的真实IP地址。基于这个IP的地理位置、运营商网络等信息，服务器通过智能调度算法，从可用的IP池中选择一个最优的（通常是延迟最低、最稳定的）IP地址返回给客户端。
4. **结果返回与缓存**：服务端通常以简洁的JSON格式返回结果，包含IP列表和新的TTL值。SDK接收结果后，更新本地缓存，并将IP返回给应用程序。
5. **建立直接连接**：应用程序获得IP后，直接向此IP发起业务请求（如HTTP请求）。关键的一点是，需要在请求的Host头中指明原始域名，以便服务器能正确识别和响应。
6. **降级策略（重要）**：为保障可用性，当HTTP-DNS服务不可用或查询超时，SDK会自动降级，使用传统的操作系统DNS解析方式作为备用方案，确保应用不会因解析服务故障而瘫痪。

### **🛡️ HTTP-DNS 如何防止本地DNS劫持**

HTTP-DNS的防劫持能力源于其架构设计上的根本性改变：

* **绕过风险环节**：传统DNS劫持发生在用户设备到本地DNS服务器之间的UDP通信上。HTTP-DNS**完全绕过了本地DNS服务器**，通过加密的HTTP/HTTPS通道直接与受信任的解析服务商通信，使得攻击者无法在传统的链路上进行劫持。
* **加密通信保障安全**：使用HTTPS协议进行查询，对请求和响应内容进行加密和身份验证。这确保了查询过程不会被窃听，也无法被中间人篡改，从技术上杜绝了劫持的可能性。
* **源头可控，调度精准**：企业可以自己部署或选择可靠的HTTP-DNS服务商，从而完全掌控解析策略。服务器能根据客户端真实IP进行最精准的调度，避免了因本地DNS IP不准确导致的“跨网访问”等问题，这本身也削弱了劫持带来的调度失准影响。

### **💡 核心价值与典型场景**

HTTP-DNS的核心价值在于**将域名解析的控制权从不可控的运营商网络夺回，交到应用开发者手中**。它特别适用于：

* **移动应用**：对网络延迟和稳定性要求高的App，如视频直播、在线游戏、大型电商App。
* **金融类应用**：对安全性和可靠性有极致要求的场景，防止钓鱼网站。
* **任何受DNS劫持困扰的服务**：希望提升用户体验和业务稳定性的所有在线服务。
