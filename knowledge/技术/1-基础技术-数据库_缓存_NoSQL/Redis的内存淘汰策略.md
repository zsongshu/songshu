# Redis的内存淘汰策略

Redis 的内存淘汰策略（Eviction Policies）用于当内存不足以容纳新写入数据时，决定如何删除旧数据以释放空间。根据 Redis 版本（≥4.0）和键是否设置过期时间（TTL），共有 **8 种核心策略**。以下是完整列表及详细说明（补充您提到的遗漏策略）：

---

### **一、****按作用范围分类**

Redis 内存淘汰策略分为两类：

* **全局策略（All Keys）**：作用于所有键（无论是否设置过期时间）。
* **过期键策略（Volatile Keys）**：仅作用于设置了过期时间的键。

---

### **二、****完整策略列表及说明**

|     |     |     |     |
| --- | --- | --- | --- |
| **策略名称** | **适用范围** | **淘汰逻辑** | **适用场景** |
| noeviction | 所有键 | 内存不足时，新写入操作直接报错（OOM），不删除任何数据。 | 数据绝对不能丢失的场景（如关键配置存储），但需严格控制内存使用。 |
| allkeys-lru | 所有键 | 内存不足时，删除**所有键中最近最少使用（LRU, Least Recently Used）**的键。 | 通用场景，适用于大部分键的访问模式符合“近期使用”的业务（如缓存热点数据）。 |
| allkeys-random | 所有键 | 内存不足时，**随机删除**所有键中的一个。 | 数据访问无明显热点，或对删除策略无特殊要求的场景。 |
| volatile-lru | 仅设置过期时间的键 | 内存不足时，删除**有过期时间的键中最近最少使用（LRU）**的键。 | 仅希望对过期键进行 LRU 淘汰（如临时会话、限时缓存）。 |
| volatile-random | 仅设置过期时间的键 | 内存不足时，**随机删除**有过期时间的键中的一个。 | 过期键的访问无明显规律，或需要快速释放空间的场景。 |
| volatile-ttl | 仅设置过期时间的键 | 内存不足时，删除**有过期时间的键中剩余生存时间（TTL）最短**的键。 | 优先淘汰即将自然过期的键（如即将失效的验证码），减少“无效数据”占用。 |
| volatile-lfu | 仅设置过期时间的键（Redis 4.0+） | 内存不足时，删除**有过期时间的键中最近最少使用频率（LFU, Least Frequently Used）**的键。<br><br>（LFU 统计键的访问频率，而非最近时间） | 过期键中存在“访问频率差异大”的场景（如高频访问的临时数据 vs 低频访问的旧数据）。 |
| allkeys-lfu | 所有键（Redis 4.0+） | 内存不足时，删除**所有键中最近最少使用频率（LFU）**的键。<br><br>（LFU 统计全局键的访问频率） | 全局键的访问频率差异大，需优先淘汰低频访问的键（如长期未使用的历史数据）。 |

---

### **三、****关键策略对比**

|     |     |     |     |
| --- | --- | --- | --- |
| **策略** | **核心指标** | **优势** | **劣势** |
| allkeys-lru | 最近访问时间 | 符合“热点数据保留”直觉，实现简单 | 无法区分高频低频访问（如某键近期被访问一次，但长期未再用） |
| allkeys-lfu | 访问频率 | 更精准识别“真正冷数据”（长期低频访问） | 统计频率需额外内存，对短周期高频访问可能误判 |
| volatile-ttl | 剩余生存时间 | 优先淘汰即将自然过期的键，减少“无效清理” | 若过期键的 TTL 分布集中（如均剩 10 秒），退化为随机淘汰 |
| noeviction | 无（拒绝写入） | 绝对保证数据不丢失 | 可能因内存不足导致服务不可用（写入阻塞） |

---

### **四、****配置与验证**

#### **1\.** **配置方式**

在 redis.conf 中通过 maxmemory-policy 指定策略（默认 noeviction）：

maxmemory 16gb _\# 设置最大内存（如 16GB）_ maxmemory-policy allkeys-lfu _\# 选择淘汰策略_

#### **2\.** **动态修改策略**

通过 CONFIG SET 命令动态调整（无需重启）：

redis-cli> CONFIG SET maxmemory-policy volatile-lru OK

#### **3\.** **验证当前策略**

通过 CONFIG GET maxmemory-policy 查看当前生效的策略：

redis-cli> CONFIG GET maxmemory-policy 1) "maxmemory-policy" 2) "volatile-lru"

---

### **五、****选择建议**

* **通用缓存场景**：优先 allkeys-lfu（Redis 4.0+）或 allkeys-lru（旧版本），平衡热点数据保留与空间释放。
* **限时临时数据**：选择 volatile-ttl 或 volatile-lru，确保即将过期的键优先被清理。
* **数据零丢失场景**：使用 noeviction，但需配合监控告警，避免内存不足导致服务中断。
* **高频低频访问差异大**：选择 allkeys-lfu 或 volatile-lfu，精准淘汰低频访问的“冷数据”。

---

### **总结**

Redis 内存淘汰策略共有 **8 种**，核心区别在于作用范围（全局/过期键）和淘汰依据（LRU/随机/TTL/LFU）。实际选择需结合业务场景（数据访问模式、是否允许丢失、内存限制），并通过监控（如 INFO memory 查看 evicted\_keys 淘汰次数）验证策略效果。
